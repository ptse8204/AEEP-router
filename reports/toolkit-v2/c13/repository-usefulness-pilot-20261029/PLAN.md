# Use the working tasks to test capability value

The next experiment asks whether optional Ponytail 4.10.0 helps an ordinary capable
Codex agent complete repository work. Further corpus expansion is deferred. The
existing AssessmentService, BenchmarkRunner, isolated workers, protected graders
and token collector run this experiment. No new engine or infrastructure is needed.

## Workload and design

The frozen cohort has 21 snapshots from 21 repositories: seven single-file repairs,
seven multi-file repairs and seven authored contract audits. Repairs cover Markdown
conversion, time handling, JWTs, bibliography parsing, environment settings and
Python analysis; multi-file cases cover release notes, simulation files, Lean and
SCIM clients, research metadata, CANopen and XML binding. The audit controls cover
game rules, edit lists, token APIs, GitHub APIs, service lifetime, configuration and
metrics. An authored audit can correctly require no change; it is not an upstream
repair relabeled as a negative task.

[The cohort record](cohort.json) gives every revision, license, source hash, declared
obligation and historical grader binding. All selected archives fit the existing
650,000-byte transport. Native-v6, oversized archives, concentrated SQLglot variants
and incompatible optional workloads are excluded from this intermediate experiment.
Selection used coverage, distinct repositories and supported transport before any
new model outcomes. It did not select favorable candidate results.

The ordinary agent and the agent with the optional skill use the same requested
gpt-6-astra model, medium reasoning effort, instructions, source, permissions and
supporting tools. There is one repetition, fresh isolated workers and the existing
paired-order schedule with seed 71. Candidate invocation is optional. All 42 task
turns count against the existing grant; nothing is refunded after a failure.
This intermediate experiment omits the stronger-compute and generated-tool arms;
those remain part of a later formal comparative design.
Source/configuration changes after this freeze require a recorded definition
review. Poor candidate performance never triggers a replacement task.

Only hash-named selected source archives enter the dedicated public directory.
Protected tests, original-source counterexamples and reference repairs remain
outside model workers. The existing archive validator rejects traversal, special
files, host configuration and embedded AGENTS files. Source and tests are read as
data during preparation; no repository code has run under this review yet.

## Why 21, and what it can decide

The working pool has 65 snapshots but only nine multi-file repositories, with many
related SQLglot issues. Seven supported, distinct repositories in each family give
a balanced intermediate experiment without waiting for more dependencies. Twenty-one
complete pairs can meet the existing minimum of 20 measured pairs for exploratory
resource analysis. Missing pairs do not become zeros or additional independent
observations. Seven per family gives limited precision.

This is development evidence. With no discordant outcomes in 21 independent
repository pairs, a simple one-sided 95% bound still allows roughly 13.3%
discordance. A zero-width empirical bootstrap interval would not prove equivalence
or exclude a five-percentage-point improvement. Public tasks also have unknown
training contamination. The experiment can expose large task differences, whether
optional instructions load, measurement gaps and observed resource variation.
It cannot establish broad absence of value or a production admission.

The exact formal requirement remains in
[the testing policy](../../../../docs/ASSESSMENT_TESTING.md#experiment-definition):
8 screening, 28 training and 105 held-out cases; qualification needs at least 100
distinct holdouts and every admitted variation. Those are requirements for the
formal acceptance campaign, not a reason to delay this development experiment.
No frozen threshold or historical result changes.

The implementation excludes development-used cases from every formal campaign
stage, including training. After model exposure, the selected repositories exclude
24 related provisional snapshots, leaving 41: 18 single-file, 15 multi-file and
8 audits. These counts are potential stock, not an adopted cohort. A later formal
balanced 141-case campaign would need at least 29/32/39 additional eligible cases
by family, plus source/stage grouping review. No more expansion follows automatically.

## Measurements and stop conditions

| Next check | Decision enabled | Stop condition |
| --- | --- | --- |
| Exact worker/collector isolation | Can these changed public-root/instruction profiles run the comparison safely? | Any policy, source, identity, collector, authority or cleanup mismatch; no model starts |
| Existing independent grader validation | Can the current retained runtime distinguish frozen correct and faulty outputs before tasks? | Any failed reference/fault check; defer the incompatible workload and stop this frozen attempt rather than install dependencies |
| Each paired task | Does optional capability availability change independently verified task success, wall time or reported tokens? | Any indeterminate execution, grade, prompt binding, token capture or cleanup stops subsequent dispatch; verified task failure remains a result |
| Canonical readback and analysis | Are the result and charges supported by original attempts, receipts and journals? | Missing or contradictory evidence blocks a complete report; retain partial results and charges |
| Actual synchronous admission check | Does AEEP refuse this unqualified development report? | Unexpected admission or changed authority/state is a defect; no identity refresh or activation is permitted |

Primary metric: paired verified task success, with family and repository breakdown.
Secondary metrics: agent wall time excluding separate grading, and provider-reported
input plus output tokens. Report raw cached/reasoning categories separately; do not
add them again to totals. Resource differences use both-successful fully measured
pairs, the existing repository-grouped interval function and minimum 20 pairs.
Predeclare Bonferroni alpha 0.05/3 for the three exploratory dimensions. Family
results remain descriptive. No bootstrap outcome overrides qualification requirements.

Positive native instruction loading is reported against the pinned skill. Absence
or unknown use remains explicit; loading does not prove semantic contribution.
Captures bind provider claims to turns and receipts; they do not independently
verify the provider meter, price subscription capacity or establish cash savings.

## What follows the result

Read the actual result before proposing more work. A negative or inconclusive
outcome does not justify searching for a favorable cohort. Report where the capable
baseline already succeeds, observed failures, measured differences and unknowns.
Decide whether a formal comparison of this candidate and workload is justified.

The synchronous admission API must reject this development report, without new
model turns or identity probes. This is actual evidence-bound restraint, not proof
that abstaining is useful on every task. Positive live selection benefit requires
independently established applicable capability value and a separate source-disjoint
selection cohort. Fixed task-family dispatch, discovery and AEEP must share inventory,
model, runtime and authority. Do not invent useful/useless labels from an inconclusive
pilot or run extra model tasks merely to demonstrate an ineligible candidate stays off.

Production resource acceptance, concrete human controls and release remain separate
open gates. Operational thresholds must come from real workload observations and
expected use. No proposed latency/memory budget becomes a hard product requirement.

## Authority and execution

The concrete review binds retained images, public disclosures, all code/assets,
fresh isolation, at most 42 task turns and conservative reservation ceilings on
the existing grant, with $0 cash. Actual consumed time is measured separately.
The proxy is reused and restored stopped; images, volumes, caches and backups stay.
No installation, download, build, new dependency, credential access or release is
included. Package, full source suite and documentation-runtime checks are not repeated.

The user continuation reserves untrusted execution/disclosure authority. Once this
exact review is approved, execute its controller once; preserve every terminal
record and stop on the listed common failures. Routine first-party definition and
finite budget bookkeeping remains delegated. An exact recorded controller/binding
correction may resume unstarted phases within the same original cumulative ceiling;
it cannot change external software, source/test/reference bytes, cohort, model,
permissions or metrics, or retry any started or uncertain invocation. This avoids
asking for the same delegated bookkeeping permission again. No architecture decision
is requested.
