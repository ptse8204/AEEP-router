# Controlled evaluator engineering journey

Connect the real ASE scheduler to an actual AEEP-controlled task, then check the
explicitly selected managed fallback through the same ordinary evaluation CLI.
These are two engine checks, each with one required-use turn. They do not compare
capabilities or measure candidate value. All comparative campaigns remain paused.

The existing public Python-Markdownify issue 200 task keeps its original source,
protected tests, reference patch and binary grading. Three previously reproduced
repository cases provide the existing grader's independent calibration fixtures;
they are not new model tasks or independent usefulness samples. No corpus expands.
The neutral `aeep-stack-check` skill is repository-authored loading/dispatch input,
with no claim of benefit. Its source is commit `38be4c0`.

One private COPY-only image adds those exact skill/license bytes to the retained
control image. It changes no executable, dependency, configuration, user or
entrypoint. Both workers keep the capable ordinary tools. Fresh inspection must
pass all 11 groups per worker and deny trial access to the trusted collector.
No model runs on failed containment. The retained ASE runtime and protected
grader image are reused. The existing model proxy starts only for this reviewed
journey and returns to its original stopped state.

Each engine uses a frozen, one-task canonical integration plan. Ordinary commands
have this form (exact generated arguments are retained before dispatch):

```text
python3 -B -m aeep_toolkit eval managed run --plan PLAN --source SOURCE
  --manifest MANIFEST --directory DIRECTORY --reviewed-digest DIGEST
  --engineering-review REVIEW --output NEW_DIRECTORY
```

Only ASE adds `--scheduler SCHEDULER`. An engine never switches automatically
after a failure. The current v2 SkillsBench workflows remain separate, unfinished
milestones; this component journey does not claim to complete either domain.

Before the second turn, canonical evidence must establish protected grading,
exact task/prompt binding, zero retries, worker cleanup, verified token capture,
positive skill loading and settled accounting. A graded failure stays a failure;
no retry is authorized. ASE must additionally retain its actual scheduler receipt
and grade-certificate observation. Upstream compatibility timing is not token or
candidate telemetry. Report each task's binary score and raw token observations;
there is no matched baseline here and no token-savings claim.

The finite review covers at most 144 existing-grant operations, two model-turn
reservations and 6,200 reserved seconds, with zero cash. These are conservative
reservation ceilings, not expected duration or operational product budgets.
Build, containment and auxiliary wrapper costs remain in the same ledger;
wrapper timing excludes nested execution and recorded setup intervals. Canonical
task costs retain their existing lineage. Whole-product accounting acceptance
remains open. Two older uncertain operations remain untouched.

No installation, download, image pull, credential reading, new provider or
destination, activation, admission or release is authorized. Only the one named
public source snapshot, task instructions and neutral skill may reach the
existing Codex destination. All images, volumes, reusable runtimes, historical
evidence and unrelated work remain. Keep the normal 50 GiB host reserve.

seven existing budget controls, two rendered-prompt controls and six actual

hashes are explicitly synthetic. No conformance evidence was fabricated in the
real database. A stale gzip profile, an extra alias in the immutable-file map and
a missing synthetic resource declaration were corrected during inert preparation.
No upstream or model attempt was consumed by those corrections.

All 13 production source checks remain passed on unchanged source `c2eb4a3d`.
The successful scanner, wheel and documentation checks keep their original
scope and are not repeated. New controller fixtures do not establish actual
worker or model success. `operation-review.json` and its exact approval are

automatically replayed. Routine bookkeeping changes for unstarted phases remain
