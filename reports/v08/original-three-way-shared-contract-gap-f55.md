# Three-way shared-contract gap, September 30

The initial wrapper was not safe to run. No campaign used it. Its exact bytes are archived as text, and the current driver rejects both validation and execution before reading a binding or constructing a Router. Equal declaration digests did not prove equivalent effective candidate access, and source-bound qualification flags did not prove grant, subject, recipe, backend, canonical completion, grader or holdout lineage. The zero-worker adversarial checks retain these findings.

The scheduler can run three routes, and AssessmentService would account for a third exact mapping dependency. That execution seam is insufficient for original experiment authority: comparison.experiment=None omits incremental lineage and differential checks. Reconstructing those checks in a report script would create a second evidence implementation.

The smallest proposed shared change is a versioned original-AEEP-value branch of the existing IncrementalExperiment, rather than a new scheduler, ledger or evidence store. This proposal has not changed source.

- In assessment/models.py, add an explicitly versioned three-way experiment variant with named normal-host, discovery-host and discovery+AEEP roles. Reuse UtilityPolicy, qualification report and DifferentialEnvironment bindings. Require exactly one additional normal-host challenger; preserve existing four-arm stage semantics and serialized bytes.
- In assessment/comparison.py, extend define/validate_incremental_hosts for that variant. Keep the latter two workers' discovery snapshot, candidate access, constraints, model and ordinary dependencies equal. Bind their expected access records to actual BoundaryConformance effective inventories and worker/configuration fingerprints. Permit only the named reviewed discovery difference for the normal host. Existing four-arm restrictions stay unchanged.
- In assessment/service.py, extend propose to compile the three named roles through the existing mapping and scheduler, and extend _verify_incremental_evidence to use its existing canonical completed-job, refit, independent grader, same grant/subject/recipe, source/backend and disjoint-input checks for this variant. Resolve every linked access/policy record and current review; membership in definition_digests alone is insufficient. Require all three current managed boundaries before each dispatch.
- In assessment/boundary.py, reuse require_conformance and require_differential validation to resolve effective inventories and enforcement definitions. A reviewed expected snapshot is a declaration; it becomes applicable only when its worker/configuration binding matches the selected actual conformance record. No bounded inspection record substitutes for full conformance.
- In assessment/reporting.py, allow the existing incremental utility loop to compare discovery+AEEP against both discovery and normal, with grouped case/template uncertainty and frozen multiple-comparison correction. Report discovery-versus-normal separately; never interpret it as AEEP contribution. Keep qualification and admission rules unchanged.

Before thawing source, review this contract extension and its exact scoped definitions. Then add adversarial source tests for equal fake records, stale/revoked records, wrong-worker bindings, unrelated qualification, source/backend drift and reused holdouts. Required full checks follow actual code changes. Worker conformance and fresh qualification remain external dependencies; no source change can manufacture their observations.
