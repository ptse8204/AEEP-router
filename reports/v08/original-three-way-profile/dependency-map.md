# Original three-way task intervention: concrete profile gap

This is inert design work on source `46803ee2814c77977c4408b60768c6581fc0189f0c8fb9a8ccd7dd77ccc4b236`. No worker, model turn, installation, test rerun or canonical authority mutation was performed. The accompanying prototype pins inspected source files and known images; null bindings remain unresolved.

The outer AssessmentService already runs all three arms through the same ledger, protected grader and attempt paths. That is common campaign machinery. The third experimental arm must separately expose a real task-only AEEP call to its evaluated agent, producing a Router decision and terminal receipt inside its own verified enclosure. Existing treatment image access to Spreadsheets alone does not provide this intervention.

The current adapter rejects AEEP skill identities, AEEP MCP server identities and route-control tools as recursive. Renaming a skill or server to avoid that guard would hide the intervention. `native_catalog` enables search flags but still disables unselected skills, so an image containing a plugin does not prove equivalent discovery access. The current three-way compiler also requires the candidate to be a skill and all supporting skills to match the normal host. These are concrete integration gaps, despite the passing schema/authority tests.

The smallest coherent extension should keep an actual model turn in both qualification and value. It can add an optional operator-owned task-profile binding to ManagedHostInvocation, leave ordinary support tools equal, and reuse the existing exposure field for required versus optional task use. A narrow verified task-profile path can expose the configured capability tool while all generic recursive/assessment targets continue to reject. Required qualification must reject absent task invocation or absent terminal receipt. Optional value must allow direct shared tools and AEEP non-use without treating non-use as failed assignment.

The task profile must reuse TaskScope ceilings, expiry, fingerprints, duration and atomic attempts. Existing scope v1 admits only native-sandbox commands; a reviewed managed-worker backend must be verified by trusted launch/conformance evidence, not a caller boolean or self-reported environment. Immutable policy and private authority/receipt storage must be denied to the model's filesystem/process tools. The concrete backend attestation and shared non-oracle executor remain design prerequisites; this report does not claim they are implemented.

Before any campaign: bind the shared operation, task-only declarations, immutable package/manifest and third image; independently verify all three final profiles; review exact access and task-scope records; materialize fresh 141-case qualification and disjoint value cases; retain canonical completed qualification, grader validation and refit; review finite budgets. Historical counts, thresholds, source evidence and four-arm experiments remain unchanged. The runtime subject is the AEEP task intervention, with Spreadsheets access common to the discovery pair; an old Spreadsheets-only qualification is not transferable.
