# Smaller skill/CLI intervention

The existing skill path already has required qualification and optional value invocation. It avoids changing MCP inventory semantics and the direct-tool legacy mode. The candidate can be an exact reviewed assessment-only AEEP intervention skill, with a narrow isolated-adapter exception for its identity and hash. All ordinary recursive AEEP skills remain rejected. The discovery baseline and third worker must expose the same Spreadsheets skill and executable operations; the normal worker alone omits the reviewed discovery surface.

The task command is `aeep tool-call --profile task --task-scope <fixed reviewed scope>`, with an immutable wrapper fixing manifest, scope, capability and approval ceiling. `aeep task` is the operator lifecycle interface and must not be exposed as this intervention. Existing Router, tool service, task outcome, scope checks, attempts and receipts supply the execution semantics. No alternative budget store is proposed.

A process-authority gap remains. An executable called through the model's shared shell inherits its filesystem restrictions. Denying the private authority database to that shell denies it to the CLI too. Allowing the model/CLI to write the same database lets the model modify reviews, counters and receipts; an immutable wrapper does not prevent direct database access. A declared protected path is therefore insufficient. A trusted existing launcher/broker must own the task store outside the model sandbox and accept only the bound task request, or an actual distinct execution boundary must demonstrate equivalent protection. No privileged wrapper, new service, permission relaxation or hidden broker has been implemented here.

The skill path is preferable for exposure reuse if that existing trusted dispatch seam can be bound. The task-MCP path naturally places the trusted task server outside the model command sandbox, but requires additional exact inventory and recursion-policy work. Both need the existing TaskScope to validate the real managed enclosure and both need an equally accessible non-oracle operation. Required qualification must prove actual task dispatch and a protected terminal receipt, not merely a skill token or a model-reported receipt. The current prototype remains non-executable pending those bindings.
