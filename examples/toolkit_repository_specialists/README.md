# Repository specialist configurations

These inert candidate wrappers make executable specialists available for a
future reviewed comparison. They are not installed, enabled, qualified or
proven useful. Their source inspection and runtime status are in the
[assembly audit](../../reports/toolkit-v2/c13/stack-delivery-20261030/README.md).

| Configuration | Candidate difference from ordinary tools | Intended task contrast |
| --- | --- | --- |
| Ordinary | No added specialist | Capable shared agent, shell, Python and ordinary editing |
| Ruff only | Ruff 0.16.2 plus `ruff-safe-fixes` | Selected safe lint cleanup |
| LibCST only | LibCST 1.8.6, pyyaml-ft 8.0.0 and `libcst-migrate` | Object/import migrations with preservation |
| Both | All three pinned wheels plus `repository-specialists` | Tasks needing both; interaction and unnecessary-use checks |

Each value configuration needs its own frozen plan and current worker binding.
Preserve every ordinary tool already present. Ruff is installed in this developer
environment and is a normal development dependency. If it is ordinary in the
target too, its exact binary stays shared across all arms; an added Ruff wrapper
is a duplicate-capability negative control or an explicitly skill-only contrast.
Do not claim added executable power or create a weak baseline by removing it.

The ordinary worker must not contain bytes belonging to the actual added
candidate difference. Individual specialist workers must not contain the other
added specialist. The combined runtime availability
image alone cannot satisfy those inventory differences. Keep model, effort,
task instruction, ordinary libraries, independent grader and run ceilings equal.
Candidate use stays optional during value trials.

Reuse the existing public repository archives and protected regression suites.
Create explicitly authored maintenance tasks for lint, migration, their combination
and neither, without claiming they are published upstream issues. Validate added
intent/preservation checks against correct, partial and destructive patches.
Development exposure cannot supply formal independent qualification or holdouts.
Do not expose the existing future-eligible stock to this demonstration.

The current paired-worker inspection supports three historical named skill
profiles. Generic specialist conformance is an implementation gap requiring a
new explicit profile contract and tests; do not label these candidates as Ponytail
or borrow its conformance. Multi-capability telemetry and actual selection remain
separate requirements. No new engine or hosted service is needed.

Use the [workflow interface](../../docs/aeep-toolkit/STACK_DELIVERY.md) to bind and
select completed reviewed plans. This example supplies candidate bytes and the
configuration design, not missing plans, receipts, grants or qualification.
